# Native QSA output projection, T1 trial

The opt-in `--native-qsa-wo-t1` path composes the reciprocal-observation Q8_1 producer with the native-order Q8_0 WO consumer. It requires the existing native QSA attention path, ordinary serial HC, eager execution, strict accelerator selection, and resident dense weights. The option is off by default. Chunked, production, alternate attention, rotated KV, and CPU fallback modes remain outside this trial.

The live gated attention tensor feeds the producer. The consumer reads that producer's packed tensor directly and its output becomes the existing FFN pending block. The Q8_0 weight is an I32 view of the existing resident `attn_output.weight` buffer; the original bytes are checked against the model role when the view is constructed. No second device weight copy is made. The added Q8_1 and output banks contain 6,912 and 10,240 bytes before backend alignment. The graph ledger charges their actual allocations and both owners; the host ledger includes the bounded input, readback, and metadata work.

Before a model attempt, run `tools/native_qsa_wo_role_preflight.py` with the six GGUF shard paths. It checks every ordinary QSA output role for Q8_0 shape `[6144, 2560]`, reports each role's SHA-256 and counts zero, normal, half-subnormal, and nonfinite scales, and refuses a missing or unsupported role. The model repeats the role and scale checks before layer construction. A produced Q8_1 image is also checked for half-subnormal or nonfinite scales before WO. Unsupported scales stop the trial; no layer is skipped.

Quantizer and WO counters report confirmed submitted and completed operations. The existing Vulkan synchronizer submits and waits in one call. If that call fails, the submission state is recorded separately as uncertain rather than guessed. A control with this option off reports zero WO work. The component comparison requires exact equality of all 6,912 packed bytes and all 10,240 projected-output bytes, including repeats and actual producer-to-consumer linkage. The supported finite-domain checks and separate literal controls remain in place.

The candidate is not a full-model parity, general reciprocal, FTZ, or performance claim. A model run is conditional on successful component comparison, real-role preflight, fresh planning and admission under the existing limits, and the existing lifecycle and cleanup controls.
