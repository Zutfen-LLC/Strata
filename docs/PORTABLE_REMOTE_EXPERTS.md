# Portable model remote expert boundary

The portable model API has an opt-in `PortableModelOptions::remote_experts` single-peer placement or `remote_expert_peers` for up to eight fixed peers. These options are mutually exclusive. Supply an existing `GpuWorkerTier::Open` for each peer with a validated immutable GPU plan and explicit Vulkan, native-Q8 and indexed-row flags. The session checks the plan against its local manifest and supplies verified source blobs for setup. The existing client enforces worker negotiation, ownership, session binding, indexed rows, readiness and transport policy, including mTLS for non-loopback Vulkan endpoints.

This slice supports serial T1 model dispatch with fixed local resident expert plans and disjoint remote plans. Mixed local and remote experts require the existing native-Q8 observation path for local devices; the older hybrid local method is refused in this combination. Before local executor setup, every remote plan is checked against the model, peer ownership is mutually disjoint, and its union is checked against every local plan; overlap refuses. Remote-owned slots are excluded from local device and CPU work. Remaining slots run through the existing local provider and its CPU complement. Prompt chunks, dynamic profile placement, CPU fallback mode and row-oracle mode remain unsupported. A remote failure is not a request to recompute on the CPU. The returned rows retain original token/slot order and remain unweighted; the existing FFN performs its normal combine.

`remote_expert_status` queries all worker counters while the session is open; `remote_expert_stats` sums client counters, and `remote_expert_peer_stats` retains each peer identity and last observed worker/client counters after close or failure. A worker status not yet obtained is explicitly marked unobserved; peers not reached during a failed setup are marked unattempted. Call `close_remote_experts` explicitly on a healthy idle session to send the bounded TLS close notification. It does not stop the shared worker; an error or destruction uses the existing nonblocking cleanup. Dynamic model-level scheduling and prompt batching remain future work.

The existing native serial PLE, HC, GDN and FFN options can be combined with this fixed ownership mode, including `--native-moe-combine`. Freeze local plans before opening the session and select remote plans disjoint from both; the local manifest binds all plans. Dynamic `--expert-native-profile` planning and `--expert-check-rows` are not supported in this combined mode. Native serial arithmetic and remote indexed rows retain their existing independent admission and failure checks. This configuration remains unqualified until exercised on the actual model and hardware.

A terminal remote transport failure or an explicit remote close makes the session unusable. `reset` refuses and leaves it poisoned; reopen the model session rather than relying on reconnection or fallback.

For each CLI peer supply `--remote-gpu-worker vulkan-native-q8@HOST:PORT --remote-gpu-plan FILE`, followed by that peer's TLS and deadline options, before starting the next `--remote-gpu-worker` group. At most eight endpoints may be supplied and each must be distinct. Endpoints are numeric; non-loopback peers require their own `--remote-gpu-tls-ca`, `--remote-gpu-tls-cert`, `--remote-gpu-tls-key`, and `--remote-gpu-tls-peer` with the expected exact DNS identity. `--remote-gpu-deadline-ms` and `--remote-gpu-setup-ms` set each peer's bounded transport and total setup deadlines. `--validate-options` checks configuration without reading plans, model or credentials and without opening a connection. A healthy completion reports total and per-peer counters and closes clients orderly without stopping shared workers. This is a bounded T1 integration, not full-model, cross-backend or performance qualification.

The opt-in `native_q8_provider_replay` test executable exercises this provider using a retained raw T2 K10 record, not a model session. It refuses a partial mask or a plan that does not own every original entry. For each token index 0 and 1, generate a fresh native direct result on the selected worker device with `vulkan_native_q8_replay --device DEVICE_INDEX --expect-device DEVICE CAPTURE RECORD PLAN BLOBS NEW_DIRECT_DIR --budget-bytes N --token-index TOKEN`. The token index retains exactly that token's ten activation/ID/weight/mask slots; no remasking is allowed. Then use a fresh worker for each slice and run `native_q8_provider_replay --provider HOST:PORT CAPTURE RECORD PLAN BLOBS DIRECT_DIR/layer.direct.reply NEW_OUTPUT --deadline-ms N --token-index TOKEN`, adding the four explicit TLS options for a non-loopback worker. The plan, capture and every selected blob must remain unchanged. Before/after worker counters require zero cumulative failures, stable residency/allocation and exactly one request and ten entries per slice; output records the original token slot association. Independently verify the input SHA-256 values, device, build, runtime and effective shaders, and inspect teardown diagnostics after each status snapshot. The two PASS files do not qualify portable CLI model execution, performance or cross-backend parity.

CPU mock and loopback tests verify wiring and protocol behavior, not native-Q8 hardware arithmetic, cross-backend parity, full-model parity or performance. A later hardware gate needs fresh same-device direct-versus-worker row evidence for the exact build, input and placement, followed by a separately scoped model test.
