# Portable model remote expert boundary

The portable model API has an opt-in `PortableModelOptions::remote_experts` single-peer placement. Supply an existing `GpuWorkerTier::Open` with a validated immutable GPU plan and explicit Vulkan, native-Q8 and indexed-row flags. The session checks the plan against its local manifest and supplies verified source blobs for setup. The existing client enforces worker negotiation, ownership, session binding, indexed rows, readiness and transport policy, including mTLS for non-loopback Vulkan endpoints.

This slice supports serial T1 model dispatch with fixed local resident expert plans and one disjoint remote plan. Mixed local and remote experts require the existing native-Q8 observation path for local devices; the older hybrid local method is refused in this combination. Before local executor setup, the remote plan is checked against the model and its ownership is checked against every local plan; overlap refuses. Remote-owned slots are excluded from local device and CPU work. Remaining slots run through the existing local provider and its CPU complement. Prompt chunks, dynamic profile placement, CPU fallback mode and row-oracle mode remain unsupported. A remote failure is not a request to recompute on the CPU. The returned rows retain original token/slot order and remain unweighted; the existing FFN performs its normal combine.

`remote_expert_status` queries worker counters while the session is open; `remote_expert_stats` preserves client counters. Call `close_remote_experts` explicitly on a healthy idle session to send the bounded TLS close notification. It does not stop the shared worker; an error or destruction uses the existing nonblocking cleanup. Dynamic model-level scheduling and prompt batching remain future work.

A terminal remote transport failure or an explicit remote close makes the session unusable. `reset` refuses and leaves it poisoned; reopen the model session rather than relying on reconnection or fallback.

The CLI enables this path only when both `--remote-gpu-worker vulkan-native-q8@HOST:PORT` and `--remote-gpu-plan FILE` are supplied. The endpoint is numeric; non-loopback endpoints require all of `--remote-gpu-tls-ca`, `--remote-gpu-tls-cert`, `--remote-gpu-tls-key`, and `--remote-gpu-tls-peer` with the expected exact DNS identity. `--remote-gpu-deadline-ms` and `--remote-gpu-setup-ms` set bounded transport and total setup deadlines. `--validate-options` checks configuration without reading the plan, model or credentials and without opening a connection. A normal healthy completion reports cumulative worker and client counters and closes the client orderly. It does not stop the shared worker. This is a one-peer T1 integration, not full-model, cross-backend or performance qualification.

CPU mock and loopback tests verify wiring and protocol behavior, not native-Q8 hardware arithmetic, cross-backend parity, full-model parity or performance. A later hardware gate needs fresh same-device direct-versus-worker row evidence for the exact build, input and placement, followed by a separately scoped model test.
