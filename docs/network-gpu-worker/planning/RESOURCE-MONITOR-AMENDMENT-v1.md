## Source components and exact contract

- `resource_telemetry.py`: typed observations, bounded procfs parsing, retained process directory FDs/pidfds, owned-descendant discovery and diagnostic host sampling. Revision 1 is source only, NOT EXECUTED.
- `resource_guard.py`: cgroup-v2 coverage resolution, fixed CPU guard and blocking monitor library seam. No workload launcher or integrated controller CLI is supplied.
- `resource_telemetry_test.py`, `resource_guard_test.py`, `resource_monitor_fixtures.py`: explicit synthetic targets, without live sampling, workloads or signals. NOT EXECUTED. The fixture runner installs traps for live operations; individual tests use doubles.

Every observation carries value/status/reason. Missing, malformed, unavailable, legitimately unsupported and numeric zero are distinct. JSON uses null for missing values; it never substitutes zero. Procfs kB fields become bytes using 1024. Host pswpin/pswpout are page counters, with runtime page size recorded separately; first-observation and previous-sample deltas are separate. Their observation start is monitor attachment, NOT a fabricated prelaunch activity baseline. A missing baseline is never silently reset. PSI exports percentages and cumulative microseconds. VmSwap, these counters and PSI are DIAGNOSTIC: no worker-only swap threshold, activity stop, debounce, 512 MiB/1 GiB host allowance or new pressure-based policy is added.

The swap guard is exactly `current_SwapFree_bytes < admission_SwapFree_bytes - 65536*1024`. Equality does not stop. One violating sample stops; the baseline never rolls or rises after recovery. Only a new separately admitted session can have a new baseline. The live monitor REQUIRES the supervisor's original prelaunch admission SwapFree value in bytes and monotonic timestamp; it refuses a missing receipt and checks an already accumulated decline BEFORE ADMITTED. Attaching cannot substitute current SwapFree or restart the7200-second clock. Preserve the original admission baseline across a monitor restart; this replacement permits no unattended restart/rebaseline. Missing/malformed SwapTotal/SwapFree blocks admission or stops owned work because this existing protection cannot be evaluated.

All owned wrapper/worker/child resource observations record PID, start ticks and executable device/inode. Held proc-directory FDs prevent subsequent status reads from following a reused numeric PID. A pidfd binds cleanup to the original process instance. Pinning checks parent identity and child PPID; sampling checks identity before/after each read. Reused identities are never added as replacements. No numeric-PID, kill-by-port or group signalling fallback exists. Descendants are discovered through every bounded task/children list, including threads that fork; previously owned descendants remain tracked after reparenting. Process/task/depth bounds are protection failures, not permission to omit coverage. Short-lived processes can exist between samples; this is sampled telemetry, not continuous accounting.

## Cgroup support and coverage repair

Supported: Linux, Python with callable pidfd_open/pidfd_send_signal, regular cgroup-v2 domain membership, one unambiguous full-root cgroup2 mount, and trusted INITIAL host cgroup/mount/PID namespace identity receipts matching both monitor and owned processes. PID/proc namespace proof precedes any pidfd pin or descendant discovery, preventing mismatched numeric PID views from binding different processes. Matching an isolated container's PID 1 is insufficient. This prerequisite must be established privately; an unverified assertion does not establish complete coverage.

Resolve actual worker membership from its pinned proc FD and mountinfo from the same verified mount namespace. Decode mountinfo escapes and map membership relative to the mount root. Walk all non-root ancestors through the actual root, recording directory identities, current usage, memory.max, memory.high and memory.events. Tightest finite `(limit-current)` across BOTH high/max and ALL ancestors limits admission/headroom. Negative room is zero. Unlimited limits still require every event guard. All high/max/oom/oom_kill counters need valid admission baselines and current readings. Any increment stops; a decrease is coverage failure. Membership, namespaces, mounts, directory identities or limits changing stops rather than rebaselining. All owned processes must remain in the covered group; spanning groups blocks this bounded replacement.

The actual root has no per-group memory.max/high/events guard; report those as unsupported true-root interfaces, not fake zeros. Root controller availability is checked. Required missing/unreadable/malformed interfaces at a NON-root group always block/stop, including when limits say max. This includes non-root controller-disabled cases; they are conservatively blocked rather than guessed safe. Missing diagnostic PSI or VmSwap remains unavailable without inventing a guard.

Blocked cases: v1, hybrid, threaded groups, subtree/ambiguous mounts, hidden ancestors, unproven/changed namespaces, unsupported pidfds, inaccessible discovery data, excessive hierarchy/process/task counts and missing required files/counters. No OS/platform expansion, controller enablement, namespace/cgroup configuration, installation or privilege change is provided. Coverage repair is stricter protection availability, not a relaxed resource threshold. Threshold trips are reported with covered guard status; discovery/protection failures report failed coverage and stop owned work.

## Unchanged limits and bounded operation

CPU admission remains BOTH host and tightest cgroup headroom >= `(107000+16384) MiB = 120.4921875 GiB`. Runtime remaining headroom must stay >=8 GiB; worker VmRSS ceiling stays 108024 MiB. The designated worker's RSS has the established ceiling; per-child RSS/anonymous/file/shared/swap observations remain separate, not a falsely unique sum. Outer ROLE_ENGINE_A/ROLE_GPU_B, GPU/scratch/reserve, disk, evidence, CPU residency/retention, all phase/global/CPU deadlines, thread counts and workload settings remain exactly as in the historical budget. This CPU-memory replacement does not implement or replace those outer safeguards.

Sampling is scheduled every two monotonic seconds. Reads cap at256 KiB; at most16 owned processes,256 tasks/process and64 cgroup ancestry nodes. Admission/sample overruns of two seconds stop at the next checkpoint. Blocking kernel I/O cannot be preempted by that check: a separately owned independent supervisor/watchdog is REQUIRED. The earliest ORIGINAL worker/trial/phase deadline must be supplied in the host's monotonic clock, including15 seconds cleanup. Never restart or extend a clock when attaching the monitor. Stop before deadline minus15; TERM owned wrapper then pinned children, grace<=15, KILL remaining matching pidfds only. Supervisor retains original watchdog/reaping duties.

New private JSONL uses exclusive creation, <=64 KiB/record and64 MiB total, within existing evidence allowance. No overwrite/rotation or accumulation. Missing/unwritable/full logs stop owned work. ADMITTED/SAMPLE/STOP markers are `RESOURCE_MONITOR_ADMITTED_V1`, `RESOURCE_SAMPLE_V1`, `RESOURCE_MONITOR_STOP_V1`. Cleanup isolates per-owner liveness/signal failures and attempts all descriptor closes even after errors. Descriptor numbers are invalidated before close, making repeated closes idempotent. An unexpected exec invalidates samples but the same pidfd/start-time task can still be stopped. STOP records attempts and exit observations, always requiring independent supervisor confirmation/reaping. It does not discover omitted children or prove post-KILL exit; discovery-cap failures and missing final receipts are incomplete cleanup, not PASS. GPU allocations and services are untouched by fixture validation.
