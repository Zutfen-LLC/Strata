# Portable native PLE host accounting — incremental inventory

Scope: source-level payloads, not allocator bookkeeping, backend internals, borrowed role/table/producer buffers, or caller-owned handle copies. `rows` is 1 or 2 in execution. Standalone composition admission sums executor, transaction, HC and component bounds before construction; it is not wired into model admission and is not an allocator-level upper bound.

* `portable_native_ple_key_batch.hpp`: one persistent 16,384-byte ggml context; constructor 65,536-byte comparison, run `2880*rows` packed bytes. Weight and source role borrowed. `host_bound` includes context and larger transient.
* `portable_native_ple_value.hpp`: per set 32,768-byte context, retained 2560² BF16 weight, retained input/output each `2560*rows` floats; constructor 65,536-byte comparison; run expected, actual, one 2560-float control row; receipt reads two input/output spans. `host_bound` conservatively sums these categories. Each T1/T2 set currently owns its own host weight copy; the device weight and source role are borrowed.
* `portable_native_ple_gate.hpp`: per set 16,384-byte context and retained key/query (`40960*rows` each), gate (`16*rows`). Verification/receipt reads one span at a time, up to `40960*rows`. `host_bound` covers these payloads.
* `portable_native_ple_grouped_norm.hpp`: 16,384-byte context per set; run simultaneously reads two `40960*rows` comparison buffers. Gamma source borrowed. `host_bound` covers these payloads.
* `portable_native_ple_conv.hpp`: per set 16,384-byte context; constructor packs 40,960 uint16 weights. Retained vectors: four inputs (92,160 + 3*10,240*rows floats), next history (92,160 floats), result (10,240*rows floats). A new run retains old snapshots while constructing new ones; source/diagnostic comparison, next history, and output/receipt vectors add transient peaks. The mismatch diagnostic can hold both source and value. The checked component helper conservatively sums these payload categories rather than proving a minimal peak.
* `portable_native_ple_copy_graph.hpp`: 1 MiB retained graph context plus owned grouped norm. `estimate` already includes graph context, so do not add its full `host_bound` again to that estimate. Borrowed producer dependencies are excluded.
* `portable_native_ple_conv_copy_graph.hpp`: 1 MiB graph context and owned convolution. The mixed estimate includes `estimate_host_bound(rows)`: graph context, packed weight and conservative convolution diagnostics, all computed with checked arithmetic. The component `host_bound(rows)` additionally includes the 16,384-byte convolution context. A composition must subtract the former with an underflow check before adding the latter.
* `portable_native_ple_gated_value.hpp`: 1 MiB graph context already included in its mixed estimate; graph producer buffers are borrowed. `host_bound` identifies that context.
* `portable_native_ple_transaction.hpp`: committed, request and output histories each 9*channels; T2 normalized and request/output residual banks, tokens and predecessor pairs are retained even for T1. Commit swaps histories. The bound includes a capped candidate/control allocation; vector capacity checks occur after allocation. Executor scratch, caller-owned handle copies, allocator metadata and callback captures are excluded.
* `portable_native_ple_executor.hpp`: shared key plus two retained T1/T2 sets, each with 16,384-byte scratch context and owners above. `estimate_breakdown` sums mixed owner estimates, component host bounds, and T2 gather payload including the simultaneous decoded row. This deliberately double-counts graph contexts and other overlapping terms. Both per-set host BF16 copies are included; borrowed roles are excluded.

Composition also includes HC role and publication banks, component factory payload bounds and a path allowance. Estimation itself uses temporary ggml metadata contexts. Capacity checks after allocation do not constrain allocator over-allocation before the check; standard-library bookkeeping, error/stream allocations and backend resources are not covered. The executor estimate alone is not a composed admission or a process-memory bound.

## Outstanding proof gaps

The current composition calculation is **not a proven production payload bound**. The previous factor-32 and 128-byte-suffix allowances have been replaced by explicit path terms in `PortableNativePleAdmission::path_host_bound`. Observation effective-stream validation now uses a fixed candidate array rather than a dynamically allocated observation vector. These changes do not by themselves prove the simultaneous-path inventory complete. The former 4096-byte allowance now names the exact `ggml_init` metadata arena requested by both factory paths; it is not a catch-all for other allocations. Do not infer that either is conservative merely because the CPU admission tests pass. Remaining work must trace constructor, run, error and candidate-receipt paths through `portable_native_ple_key_batch.hpp`, `portable_native_ple_value.hpp`, `portable_native_ple_gate.hpp`, `portable_native_ple_grouped_norm.hpp`, `portable_native_ple_conv.hpp`, both copy-graph owners, and their production Vulkan component creation and run functions. In particular, account for retained old snapshots alongside new comparisons, nested estimate contexts, filesystem/string and diagnostic temporaries, and production dispatch input/diagnostic buffers; validate production extents before allocation. Independent component accounting and a combined actual-construction exact/one-byte-short test are still needed.

Allocator metadata and capacity slack, ggml opaque bookkeeping, external backend and driver internals, and caller-owned copies are excluded; source-controlled payloads are not excluded merely because they occur in diagnostics or factory code. CPU mock tests do not prove production Vulkan paths.
