# Native GDN output projection, T1 trial

The default-disabled `--native-gdn-output-projection-t1 PREFIX` path uses the completed ordinary GDN recurrence's gated output for the existing 6,144-element Q8_1 producer and native-order Q8_0 output projection. Its 2,560-element producer-owned output is passed directly to the native FFN HC pending read. The existing residual and recurrent-state transaction still commits only after FFN succeeds. Layer 1 PLE is unchanged.

The trial requires ordinary serial HC with its FFN read, resident dense weights, and native GDN preparation and recurrence. It rejects fused `STRATA_QFUSE` and existing unsupported batch, production, or fallback modes. The existing resident `ssm_out.weight` Q8_0 allocation is borrowed without a second device weight bank; its bytes are checked against the model role. The new packed and output banks, native owners and diagnostic host work are admitted against the existing budgets. Work counters report submitted, completed, and uncertain producer/consumer operations.

Before physical qualification, run `tools/native_gdn_output_role_preflight.py` on the six ordered model shards. It requires the 35 ordinary `ssm_out.weight` roles to be Q8_0 with shape `[6144, 2560]`, records each role's hash and scale classes, and rejects nonfinite weight scales. Finite half-subnormal weight scales are accepted under the existing WO control. Produced Q8_1 scales retain the stricter existing 192-block domain: half-subnormal and nonfinite stored scales are refused. The separate 80-block QKV producer qualification does not extend that domain.

Use the existing native-first QSA WO composition fixtures, unchanged native quantizer and MMVQ launcher, and exact 6,912-byte packed plus 10,240-byte output checks. The mapped `native_gdn_output_model_control` accepts six shard paths, an ordinary layer, the packed input and output, then checks the actual `ssm_out.weight` role in native reduction order. Local host-provider tests exercise producer ownership and transactions, not CUDA/Vulkan parity. Real role scan, current native method selection and instruction review, guarded component comparison, and fresh model admission remain required. This path makes no full-model parity or performance claim.
