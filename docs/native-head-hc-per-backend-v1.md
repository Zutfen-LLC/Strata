# Head HC per-backend primitive contract, version 1

This is a new diagnostic numerical criterion for the opt-in, materialized T1 output-head HC mixer. It follows the existing `native-hc-normal-v1` and `native-hc-mix-sigmoid-tails-v3` per-backend contracts. It does not alter the previous frozen exact checker or its STOP. Cross-backend word differences remain visible; no final-output epsilon, fitted bound or CUDA-intrinsic emulation is introduced. A numerical result is only one gate and does not establish full-model parity, quality, performance or general hardware equivalence.

The fixed five synthetic fixtures, exact input bytes, native staged variant 3, actual producer, repeat/canary, domain refusal, device/module identity, exit/reap, admission and cleanup remain required. Each backend independently uses the existing source-order square and XOR/warp reduction, existing rsqrt and exp bounds, and its own captured RS for exact weighted normalization. The mixer uses the existing exact ordered BF16/F32 FMA, chunk and XOR controls and each backend's own low input for its up dot. The head-only candidate additionally requires exact RNE SiLU division by the denominator formed from its own captured Vulkan exponential. It keeps the existing Vulkan sigmoid own-exp quotient and exact own-gate ordered mixed-output checks.

**Native gate capture limit:** the unchanged native launcher exports low and mixed, but not individual up-dot, exponential or gate words. The established native mixer validator computes the exact up dot from that backend's captured low and checks mixed output against the existing bounded native activation propagation. It cannot assert exact association with a captured native gate or uniquely localize individual native gates. This is a real difference from Vulkan's exact own-gate check, not an assertion that both backends supply the same evidence. The separately captured primitive observation covers its one fixed input only. Extending native gate export requires its own method/instruction review; it is not inferred or fabricated here.

`tools/compare_native_head_hc_contract.py CASE NATIVE_DIR VULKAN_DIR NEW_REPORT` reports per-backend controls, exact RNE SiLU and cross-backend differing-word counts under contract `native-head-hc-own-primitives-rne-v1`. The `--retained-observation` switch is diagnostic only and always sets numerical acceptance false. Its purpose is to inspect the original captured shader, not to qualify the new shader. Candidate mode's numerical acceptance does not authenticate source, module, binary or hardware by itself: the guarded component qualification must independently bind the actual new head-only shader/effective modules and all other evidence. Existing failures and reports remain immutable.

The retained exact comparison stopped on cancellation. Offline inspection of the authenticated five retained captures found that all satisfy the existing individual backend source/primitive controls; the old Vulkan output differs from exact RNE SiLU in 1 cancellation, 72 dense and 1 sparse low words, and in none of the tails or zero low words. Those historical observations are not a new candidate pass. New device output is needed for the head-only RNE variant, while the unchanged native captures may be reused only after their exact source, input, method, binary, instruction, fixture and evidence bindings are verified.
